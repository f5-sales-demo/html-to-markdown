# Qualified policy activation on installed workers

Delivery #155 and curation renewal #167 depend on implementation #179. A merged catalog
is a source change; installed workers must activate its exact qualified bytes separately.

The Mac worker synchronizes policy before each queue sweep under its worker lock. Ubuntu
exports only current protected-main files from the declared repository. It verifies the
complete public catalog/evidence set, independent whole-corpus qualification receipt,
zero enforcement findings, installed Python controller digest, and unchanged API policy
and destination catalog. Changed software or API policy requires a compatible release.
Raw captures, native responses, OCR and identifying transformations remain private.

Each host stages an immutable digest-addressed bundle before replacing its active pointer.
Ubuntu activation and confirmation hold the existing publication coordinator lock, then
the activation lock. Mac activation remains under the worker lock. A changed activation
clears its old cohort confirmation; repeating the identical activation preserves it.
Interrupted activation, superseded protected-main inputs, tampering and a missing peer
confirmation block new publication while the deployed verified snapshot continues to serve.

Confirmation rechecks protected-main policy and software before recording agreement.
Publication checks both the recorded host agreement and current protected-main inputs.
A prepared job's fingerprint includes the active curation policy, so a policy change
supersedes the job while preserving its evidence. Assembly still uses the latest verified
deployed baseline; a delayed review cannot replace newer official documentation.

The default policy state is the user's private `html-to-markdown/policy` directory.
`HTML_TO_MARKDOWN_POLICY_STATE` can select another stable private location. Ubuntu
repository routing uses `HTML_TO_MARKDOWN_POLICY_REPOSITORY`. On the Mac, remote policy
state defaults to a sibling of the configured remote queue and can be selected through
`HTML_TO_MARKDOWN_REMOTE_POLICY_STATE`. These settings contain paths, never credentials
or provider overrides. The existing authenticated SSH transport and Codex provider remain
the execution routes.

## Privacy phase dependencies

The `source-privacy/2` binding covers complete article bytes, relevant metadata, media,
privacy policy and controller semantics. Global retirement/API catalog pins belong to
relevance and final admission, rather than the privacy request. Catalog-only changes
therefore rerun relevance and independent final validation while eligible completed privacy
and native-observation phases replay under their exact requests.

A proposal without complete independent privacy, extraction, media and preservation proof
is not a completed reusable privacy decision. Changed source, metadata, media, controller
semantics or failed results cannot reuse approvals. Every reused response is reparsed and
verified when consumed; final credential enforcement is mandatory. Original correction
feedback and exhausted two-correction limits survive repeated catalog changes. Historical
version-one responses retain their original exact contracts and are not migrated into
version-two approvals.

Clipped identifying screenshot regions must exclude visible boundary quotation marks.
Native confirmation checks the exact rectangle, and the privacy editor preserves those
pixels outside its unquoted label. It cannot erase a visible delimiter or invent hidden
punctuation. Independent complete-media preservation remains required.
