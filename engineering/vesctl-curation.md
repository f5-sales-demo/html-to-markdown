# Whole-document CLI retirement

The versioned `vesctl-retired` topic omits an entire document when its original
title, authored metadata, body, code, image caption, or link destination contains
vesctl. Matching is case-insensitive and decodes nested percent, HTML entity,
JSON character, and Markdown escapes. The original input guard runs before
another topic can erase the mention. Dependency edits run between AppStack and
Terraform through the shared normal and offline planner. No substitute link,
notice, or placeholder is added.

The receipt-verified baseline is `content-20261005T134122Z`, with publication
SHA-256 `281d82bb7841b4ad58cdf3958ffca09ebf2497d8dc4817a0f9ce713979876aae`.
Its 739 documents contain ten direct matches, including the Console, WAF, and
DDoS product pages. `vesctl_review.json` records every removal and the fourteen
retained pages with incoming links. Exact input, replacement-count, and output
digest guards preserve standalone prerequisites and actions, remove optional
notes and related items, remove affected product cards, and unlink solution
headings while retaining their explanations. New or changed dependencies are
omitted until reviewed; other topics cannot erase their dependency evidence.

The baseline contains fifteen derived relationship entries across twelve
retained pages that point to removed documents. Curation prunes the entries and
rebuilds descriptions, relationships, reports, document hashes, checksums,
archives, and unused assets. The planner retains exactly 729 baseline pages with
no unrelated omissions. Manifest schema v2 and CLI arguments remain unchanged.

`vesctl_media_review.json` pins OCR decisions for all 3,558 unique baseline
assets (3,822 occurrences). Raster images use Tesseract; SVGs are rendered using
CSS fallbacks or Chromium with network access disabled. The one confirmed
image reference belongs to an already removed debug-command page. Its digest
also omits any future page that reuses those bytes. The 247 affected media
occurrences were reviewed through contact sheets and the detected image was
inspected at its original size. Retained source image bytes remain unchanged.

Detailed decisions and stage digests stay in `curation-audit.json`, outside
consumer archives, release assets, and Pages. The intentional reader-facing
policy mention lives in `docs/index.mdx`; captured documents and collection
navigation contain no reference.

Verification covers encoded and case variants, original metadata, code, links,
captions, confirmed image bytes, source guards before other topic edits,
independent dependency repairs, changed inputs, offline reapplication, restored
pages, and normal fetch/extraction. Release acceptance additionally compares two
offline builds from the same verified input, checks the complete retained
relationship graph and assets, and verifies the deployed receipt and Markdown
inventory using the workflow's immutable builder and verifier pins.
