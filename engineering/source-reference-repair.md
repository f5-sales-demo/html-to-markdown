# Source reference repair

A source renderer can produce a broken image reference while a reviewer correctly
refuses publication. Correcting that renderer does not grant another editorial
proposal. The source reference repair path preserves the original context, every
response and the exhausted attempt ledger, then verifies a new input separately.

Preparation accepts only duplicated media extensions whose repaired references
resolve to the same content-addressed asset bytes. Every image placement remains.
Other text, source dates, identifying values, image bytes and media observations
must remain unchanged. Native derivative digests may change only through current
compiler replay. Captured HTML, original relevance/privacy evidence and the
original curation input must identify the same article.

```bash
html-to-markdown prepare-reference-repair \
  --output private-review \
  --original-binding ORIGINAL_DIGEST --attempt ORIGINAL_ATTEMPT \
  --capture private-capture --source-record private-source-record.json

html-to-markdown review-reference-repair \
  --output private-review --repair-binding REPAIR_DIGEST
```

The first independent review checks the complete source, privacy transformation,
all media and every remaining unresolved condition. It grants no retirement or
publication approval. Credential enforcement findings cannot be approved. A
compiler input then projects the original topic decisions through exact guarded
reference changes; it is never a rebound model response. A second independent
review checks all curation stages, facts and media, including the mandatory final
whole-document review. Failed or ambiguous conditions stay queued.

Use `review-reference-repair --replay` for offline verification. Ordinary curation
replay also reconstructs the source repair and both reviews before the governed
planner can use the result. The original attempt count and feedback remain
unchanged. Raw captures, OCR, responses and transformation evidence stay private;
CLI summaries report only digests, counts and pending publication status.
Captured OCR is part of the source-repair digest. Offline replay preserves that
evidence and regenerates complete native images from the preserved asset bytes,
checking every frame, pixel derivative, timing and metadata guard. It does not
replace reviewed OCR with results from a different host's OCR installation.

## Complete native image inputs

Source and candidate screenshots can have identical complete pixels with different
PNG encodings. Requests that fit native capacity retain their original attachment
order. Larger requests first share identical encoded images using manifest version 1.
Only if those attachments still exceed capacity does version 2 share images
whose complete RGBA pixels, original-mode pixel bytes, dimensions, mode, palette
and all metadata match exactly. Neither the image count nor decoded capacity limit
changes. Distinct oversized inputs still require complete image-boundary review.

Version 2 binds every original encoded-image digest and logical placement to its
native attachment. Replay reconstructs and verifies this mapping from the unchanged
logical request; each placement still needs contextual source, privacy and curation
review. Changed pixels, alpha, palettes or metadata cannot share an attachment.
Animations require separate complete frames. Both manifest versions remain valid
for their original inputs; failed attempts and stale cache evidence remain private.
